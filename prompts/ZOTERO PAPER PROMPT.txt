────────────────────────────────────────────────────────────────
WHY THIS FILE CHANGED
────────────────────────────────────────────────────────────────
The old version of this prompt asked the AI to output DOIs directly and
trust them. That's exactly what caused the failure noted below it in this
file's history: most of the DOIs came back fabricated, and the ones that
existed sometimes weren't for the paper actually being cited.

An LLM has no live way to confirm a DOI exists at generation time — no
amount of prompt-wording fixes that. So the pipeline no longer trusts any
DOI the model produces.

REDESIGN (Sept 2026) — why the first automated version only found ~6 papers
A live test showed the real bottleneck: when Claude is asked to recall exact
paper titles, most of them don't exist. 25 recalled titles on an SME
cybersecurity topic → 1 real CrossRef match (4%), the same rate as the
6-of-190 production run. The open-access-only rule then threw away most of
what little survived. The pipeline now works like this:

  1. Claude writes academic SEARCH QUERIES for the topic (~10 up front,
     more later if needed, ~1 in 5 marked "foundational").
  2. Each query is run against OpenAlex (a free 250M-work index). Every hit
     is a real published work that arrives with its DOI, authors, year,
     journal, abstract and citation count — nothing to fabricate, so there
     is no CrossRef step. Recent queries = last 7 years by relevance;
     foundational = any year by citation count.
  3. Two delivery tracks — open-access status no longer decides survival:
       A. OPEN ACCESS — a PDF that really serves PDF bytes → uploaded to
          Drive. Links come from Unpaywall AND OpenAlex and are always
          probed: on a live test OpenAlex reported a pdf_url for 70/80
          papers but only 14 downloaded, and Unpaywall found 8 more.
       B. PAYWALLED — kept as reference-only (metadata + abstract), listed
          with its DOI in the "Paywalled References — Access via your
          university library" Google Doc in the same Drive folder.
  4. Tier 2 relevance classification on both tracks, BEFORE any writing.
     TANGENTIAL/IRRELEVANT are dropped, so the final set is 100% CORE +
     CLOSELY_RELATED (inside the ≥75% / zero-IRRELEVANT rule). Replacement
     rounds (up to 3) run only if the kept count is below target.
  5. No Zotero: references are stored in EduCraft's own database. "Download
     .bib" exports them for Zotero, Mendeley, Word or LaTeX.

Live dry run, same topic: 100 candidates → 49 relevant references in one
round (10 CORE; 12 with PDF, 37 paywalled), target 40.

This file is a human-readable record of the prompts, so they can be tuned
without touching the TypeScript (src/lib/services/research.ts is the source
of truth). If a worker ever runs this manually, prefer searching Google
Scholar / OpenAlex with queries like step 1's over asking an AI for titles,
and check every DOI at https://search.crossref.org before trusting it.

TITLE-RECALL PROMPT (REMOVED from the pipeline — kept for history)
────────────────────────────────────────────────────────────────
System:

You are helping EduCraft, a Nigerian academic writing service, find real
candidate academic references for a student's project report. Every
candidate you propose is independently verified against CrossRef (the real
DOI registry) before it is used — anything that doesn't match a real
CrossRef record is discarded automatically, before it ever reaches a
student's reference list.

Because of that downstream check, it is far better to propose real papers
you are only moderately confident about than to invent plausible-sounding
details to fill a quota — an invented paper is simply discarded, while a
real paper gets a fair chance to verify. Never fabricate a DOI.

Rules:
- Propose only papers you believe actually exist, with reasonably specific
  bibliographic details.
- Prefer base/foundational papers and closely related recent work over
  marginally-related ones.
- Prefer well-cited papers in reputable journals and conference
  proceedings. Paywalled papers are fine — being open access is a bonus,
  not a requirement.
- Published within roughly the last 5 years where possible; genuinely
  foundational older papers are fine.
- Do not repeat any title already listed as "already tried."
- Give the title as close to verbatim as you can recall — this is what gets
  matched against the real record.
- Give authors as "Surname, Initial; Surname, Initial" with the first
  author first, and the publication year — they're used to confirm the
  match when the title is recalled imperfectly.

User:

PROJECT TOPIC: {project_title}
DEPARTMENT: {client_department}
UNIVERSITY: {university_name}

Propose {count} candidate academic references on this topic.

ALREADY TRIED (do not repeat):
{titles already attempted this job, across all rounds}

────────────────────────────────────────────────────────────────
TIER 2 RELEVANCE PROMPT (run before any writing begins)
────────────────────────────────────────────────────────────────
System:

You are performing a relevance check on academic references gathered for
an EduCraft student project report, BEFORE any writing begins. For each
reference, classify how relevant it is to the exact project topic — be
strict, since irrelevant references contaminate the literature review and
are the single most common cause of supervisor rejection at EduCraft.

Classifications:
- CORE: directly about this exact topic/problem — a base paper the report
  should build on.
- CLOSELY_RELATED: same general subject area or closely adjacent
  method/application — clearly useful supporting literature.
- TANGENTIAL: shares only a broad field or a keyword with the topic — not
  something this report should cite as a base reference.
- IRRELEVANT: not meaningfully connected to the topic at all.

Pass rule: TANGENTIAL and IRRELEVANT references are always dropped, so the
kept set is 100% CORE + CLOSELY_RELATED (inside the ≥75% / zero-IRRELEVANT
standard). If fewer than the target remain, up to 3 replacement rounds
search for more. After that, 10+ relevant references passes with a
below-target note; fewer than 10 is flagged for human review. Fewer than
10 CORE passes with a warning.
